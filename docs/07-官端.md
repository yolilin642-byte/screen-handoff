# 第 7 章 · 官端用它：App 里的 AI

> 适合：ChatGPT 这类住在别人服务器上的 AI，手机 App、网页都算。
> 这一章做完：在 ChatGPT 的对话里说「看一眼我的屏幕」，它截一张图来看；让它去网页上办件事，它在你电脑的 Chrome 里点，屏幕底下的字幕写着「GPT：……」；叫它打开直播，对话里长出一张卡，你在卡里看画面、点画面、按「我来」。
> **只在 ChatGPT 上走通过**（2026 年 11 月，安卓 App）。Claude 官端按理能接同一个连接器，没测过，见本章最后。

第 6 章的 AI 住在你电脑上，伸手就够得着小程序。官端的 AI 住在服务商的机房里，够不着你家，得在 VPS 上放一个**连接器**替它传话：

```
ChatGPT（OpenAI 的服务器）
  └─ https ──> 连接器（VPS 上，127.0.0.1:39271，Caddy 转进来）
                 ├─ 授权：OAuth，授权页上填「新设备的码」
                 ├─ 看屏幕、浏览器那几样 ──> 127.0.0.1:39260 ──隧道──> 家里小程序 5261 ──> hand / OpenCLI
                 └─ 直播卡 ──> 卡里套一扇你的网页客户端（第 4 章那份）──画面直连电脑
```

工具和直播卡是两件事，互不依赖：不开卡，GPT 照样能看屏幕、点网页；开着卡，GPT 也看不见卡里的画面。**GPT 看得见的只有它自己调「看屏幕」截的那几张。** 卡往回报的只有连没连上、帧率这类字，不带画面。

---

## 1. 要准备的

- 第 1–5 章都做完：信令、CrossDesk 主机端、门、网页客户端、小程序、隧道（家里的 5261 经隧道接到 VPS 的 39260）。
- 想让 GPT 上网，还要第 6 章的 OpenCLI 和那道闸。不装的话，「看屏幕」能用，浏览器那几样会报错。
- 一个能加自定义连接器的 ChatGPT 号：要在设置里打开开发者模式才加得了。哪些套餐开得了，以 OpenAI 当时的说明为准。
- VPS 上有 Python 3（我们是 3.12）。连接器只用标准库，不用 pip 装任何东西。

## 2. 放文件

把仓库的 `connector/` 拷到 VPS，比如 `/opt/screen-connector/`：

| 文件 | 干嘛的 |
|---|---|
| `server.py` | 连接器本体：MCP、OAuth、把工具调用转回家 |
| `live.html` | 直播卡 |
| `site.json` | 第 4 章那份，原样拷一份。连接器从这儿读域名、设备号 |
| `path.txt` | 连接器的地址路径，自己生成（下面） |
| `relay.key` | 跟电脑上 `deploy/door.json` 里的 `g` 一模一样（第 5 章第 3 步生成的那把） |
| `oauth.json` | 不用建，头一回授权时它自己写 |

```bash
cd /opt/screen-connector
echo "/mcp-$(openssl rand -hex 8)" > path.txt
printf '%s' '<连接器钥匙>' > relay.key
chmod 600 relay.key
```

路径藏起来，只是让扫端口的机器人摸不到门口。**真正的锁是 OAuth**：没授权的，一律 401。

## 3. 让它常驻

`/etc/systemd/system/screen-connector.service`：

```ini
[Unit]
Description=screen connector (MCP + OAuth)
After=network-online.target

[Service]
User=<你在 VPS 上的用户名>
WorkingDirectory=/opt/screen-connector
ExecStart=/usr/bin/python3 /opt/screen-connector/server.py
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now screen-connector
systemctl is-active screen-connector    # active
```

它只听 `127.0.0.1:39271`，外面直接敲不到，要经 Caddy。

## 4. Caddy：把三样东西转给它

OAuth 的授权服务器就是你的域名本身，所以除了连接器那条路径，域名根上的 `/.well-known/…` 和 `/oauth/…` 也要转给它。加在第 3 章那段 `<你的域名> {` 的**最上面**：

```caddy
	# OAuth：元数据、注册、授权页、换令牌
	@mcpoauth path /.well-known/oauth-protected-resource* /.well-known/oauth-authorization-server* /.well-known/openid-configuration /oauth/*
	handle @mcpoauth {
		reverse_proxy 127.0.0.1:39271
	}
	# 连接器本体（<连接器路径> 换成 path.txt 里那串，带开头的 /）
	handle <连接器路径> {
		reverse_proxy 127.0.0.1:39271
	}
```

第 5 章加的那段 `handle /api/agent/gpt* { respond 403 }` 要留着：工具调用只许 VPS 本机的连接器直接敲 39260，从外面经域名来的一律挡。

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

## 5. 验：先别急着接 ChatGPT

从外面（你的电脑就行）：

| 敲法 | 应该 |
|---|---|
| 浏览器开 `https://<你的域名>/.well-known/oauth-protected-resource` | 一段 JSON，`resource` 是 `https://<你的域名><连接器路径>` |
| `curl -i -X POST https://<你的域名><连接器路径>` | 401 |
| `curl -i -X POST https://<你的域名>/api/agent/gpt` | 403 |

再在 VPS 上，确认连接器那把钥匙跟家里对得上：

```bash
cd /opt/screen-connector
curl -s -X POST http://127.0.0.1:39260/api/agent/gptpair \
  -H 'Content-Type: application/json' -H "X-Kael-Relay: $(cat relay.key)" \
  -d '{"code":"000000"}'
```

| 回 | 意思 |
|---|---|
| 「配对码过期了……」或「配对码不对」 | 钥匙对上了（码本来就是乱填的） |
| `{"ok": false}`，HTTP 403 | `relay.key` 跟电脑上的 `g` 不一样 |
| 连不上、502 | 隧道没通，回第 5 章第 6 步 |

## 6. 在 ChatGPT 里接上它

> 菜单名照 2026 年 11 月的样子写，OpenAI 常改。

1. 设置 → 应用（Apps / Connectors）→ 高级，打开开发者模式。
2. 新建一个，地址填 `https://<你的域名><连接器路径>`，认证选 **OAuth**。
3. 它会跳出一页「允许 ChatGPT 用你的电脑？」，要一个六位数。去一台进过门的设备（操控台、你的聊天页里的小屏）点「新设备的码」，十分钟内填进去，点「允许」。头一回谁都没进过门，就在电脑上要（第 5 章第 7 步）。

码只能用一次，家里核过就作废；填错五回也作废，再要一个就是。授权以后，令牌一小时一换，ChatGPT 自己续；续期的那张三十天，三十天里一回都没用过，才要重新授权。

## 7. 试一下

开一个新对话，把这个连接器选上，说：

- 「看一眼我的屏幕」：它调 `screen_look`，拿到一张 1280 宽的整屏截图。
- 「打开 example.com，告诉我标题」：它调 `browser_open`、`browser_state`。头一回要新开一扇 Chrome 窗，十秒上下；之后一秒出头。
- 「打开直播」：它调 `screen_live`，对话里长出直播卡。

**每一下 ChatGPT 都会先弹出来问你。** 这是故意的：连接器把所有工具都标成了「不是只读」，ChatGPT 见了就先问。弹出来的框里有「始终允许」，点了，这个对话里它再看屏幕、点网页就不问了。我们家点过；查到的说法是这份允许只管当前这个对话，换新对话会不会再问，我们没留意过。

GPT 能用的一共十样：

| 工具 | 干嘛 |
|---|---|
| `screen_look` | 截整块屏幕 |
| `browser_open` | 在它自己那扇 Chrome 窗里开网址（只认 http/https） |
| `browser_state` | 读这一页：网址、标题、带编号的可点元素 |
| `browser_extract` | 读这一页的正文 |
| `browser_click` / `browser_type` / `browser_keys` / `browser_scroll` / `browser_back` | 点、打字、按键、翻页、后退 |
| `browser_close` | 关掉它开的那扇窗 |

它开的窗是你的 Chrome（OpenCLI 借的），**登着号的站在它手里也是登着的**。它不关窗也没关系：十分钟没再碰浏览器，家里替它关；你按着「我来」或者刚碰过电脑，就再往后推十分钟，免得你正接着用。

一次只做一件：上一下还没做完，下一下回「The previous action is still running」。

## 8. 直播卡

卡里套的是你的网页客户端（`https://<你的域名>/#embed&card&id=<设备号>`），画面从电脑直连到你手机上，不经过 OpenAI，也不经过连接器。

- **头一回**：卡说「门上了锁」，要配对码。还是去进过门的设备点「新设备的码」。这台手机配过一次，以后不再问。
- **每一回**：输 CrossDesk 的密码。卡不记密码。
- **自己会断**：半小时没碰（快到时提前半分钟提醒，碰一下接着用）、切出去一分钟、按左上角「断开」。断了要连就再输一次密码。
- **「我来」**：按下，GPT 的下一下就被挡回来，它收到的是「The user is holding control」，会停下来告诉你。GPT 正干着一下时按，卡上先写「正在松手」，等那一下真停了才说你接手了；它截的图还没回来时被按住，那张图也不交给它。按「还给你」，它接着干。

**卡多半头一回连不上**，写着「电脑那页没认出这个框（mcp-endpoint-…）」。这是第 4 章说的那道检查：网页客户端只认 `site.json` 里 `cardOrigins` 列着的外层，ChatGPT 给每张卡的外层是一个它自己起的网址，事先不知道。去 VPS 上翻：

```bash
tail -n 1 /opt/screen-connector/reports.jsonl
```

那一行里 `origin` 后面那串（我们家的长这样：`https://mcp-endpoint-<一长串>.web-sandbox.oaiusercontent.com`）抄进 `site.json` 的 `cardOrigins`，照第 4 章重新生成首页、传上 VPS，再叫一张新卡。

我们家只有一个连接器地址，这串跟着什么变，没试过；换了连接器地址，最好当它也变了，照上面再抄一回。

## 9. 撤掉它

从轻到重：

- **ChatGPT 里删掉这个连接器**：只是这个号不连了。
- **作废所有授权**：VPS 上把 `oauth.json` 换成 `{"clients":{},"tokens":{}}`。当场生效，不用重起，它每一下都现读这个文件。手机丢了、号借出去过，就做这一步。
- **换连接器钥匙**：电脑上 `door.json` 的 `g` 和 VPS 上的 `relay.key` 一起换，再 `sudo systemctl restart screen-connector`（连接器只在起来时读一次，家里那头每一下都现读）。
- **整个停掉**：`sudo systemctl disable --now screen-connector`。

## 安全

- **GPT 看到的截图会送到 OpenAI。** 屏幕上开着什么，它就看得见什么。
- 授权页上写着它能干什么：看整块屏幕；在你的 Chrome 里开网页、点、打字，登着号的站也算。
- **这条路比第 6 章硬**：GPT 手里没有放开「我来」的工具，也没有那个不管你碰没碰过鼠标的参数，它绕不过去。「我来」按着，或者你四秒内碰过鼠标键盘，它的每一下都被挡回来。
- 外面直接敲 `/api/agent/gpt`，Caddy 先挡一回；漏过去了，家里的小程序再查一回连接器钥匙。
- OAuth 的注册谁都能来（ChatGPT 就是这么头一回连上的），可没有码过不了授权页。
- 连接器给 GPT 的说明里写了：不替你买东西、付款、删东西、发消息发帖，除非你明说要它做这一件。**这一条靠它守规矩**，工具本身拦不住它在网页上点「发送」。
