# 第 0 章 · 准备

> 这一章不动手，只对一下：要哪些东西、按什么顺序走、一路会攒下哪几把钥匙。

---

## 1. 要哪些东西

| 东西 | 干嘛 | 非要不可？ |
|---|---|---|
| 一台 Windows 10／11 电脑 | 被看、被点的那台。要一直开着、别睡 | 要 |
| 一台 VPS（Linux，有公网 IP） | 放信令、门、网页，第 7 章的连接器也在这儿 | 要。只想在手机上看画面，可以借官方公共信令，见 README 家型 3 |
| 一个域名 | 给 VPS 一个带证书的 https 地址 | 跟 VPS 一起要 |
| 一台放中继的机器 | 直连打不通时转画面 | 不急，第 8 章再说；跟 VPS 同一台也行 |
| Node.js 18 以上 | 跑电脑上的屏幕小程序 | 要 |
| Chrome，加 OpenCLI | AI 在你登着号的网页上点 | 想让 AI 上网才要 |
| 能加自定义 MCP 连接器的聊天应用（走通过的是 ChatGPT） | 第 7 章 | 只有官端聊天应用要用才要 |

**VPS 放哪**：放国外。国内的机器，没备案的域名 443 端口会被掐，我们家撞过。中继不受这个管，可以放国内。

**我们家的**：信令那台是甲骨文东京的免费机（1 核 1G，够用）；中继是另买的腾讯云广州；电脑是一台不关机的 Windows 11。

## 2. 一路要做的事

会要你在 VPS 上敲命令（SSH 登进去）、改几个文本文件，在电脑上开 PowerShell。要敲的命令都写全了，照抄、把尖括号里的换成你自己的就行。

全文用这几个占位：

| 写作 | 换成 |
|---|---|
| `<你的域名>` | 比如 `screen.example.com`，不带 `https://` |
| `<VPS 的 IP>`、`<中继的公网 IP>` | 那台机器的公网 IP |
| `<门牌>`、`<钥匙>`、`<连接器钥匙>`…… | 你自己生成的钥匙，见下面第 4 节 |
| `<仓库目录>` | 你把这个仓库放在电脑上的哪儿 |

## 3. 按什么顺序走

先挑你要哪一种：

| 想要 | 走哪几章 |
|---|---|
| 只在手机上看、点自己的电脑 | 1、2、3、4 |
| 再加：电脑上的 AI（任何能跑命令的 Agent）替你干活，你在手机上看着、随时接手 | 再加 5、6 |
| 再加：官端聊天应用替你干活 | 再加 5、7（让它上网还要 6 的 OpenCLI） |
| 换个网就连不上 | 8 |
| 哪儿不对了 | 9 |

每章开头一行写着「这一章做完」是什么样，每章末尾都有一步「验」。**验过了再往下走**，别攒着一起验：哪一截坏了，在那一章当场就看得出来，攒到最后就分不清了。

## 4. 一路会攒下的钥匙

先在一个只有你看得见的地方（密码管理器最好）开一页，攒到一个记一个：

| 钥匙 | 哪章生成 | 放在哪 |
|---|---|---|
| CrossDesk 的密码 | 第 2 章，CrossDesk 窗口里 | 只在窗口里看，不往别处写 |
| 门牌 | 第 3 章 | VPS 的 Caddyfile、电脑上 CrossDesk 的 `config.ini`、电脑上 `deploy/door.json` 的 `h` |
| 门钥匙 | 第 3 章 | Caddyfile、`door.json` 的 `w` |
| 连接器钥匙 | 第 5 章 | `door.json` 的 `g`、VPS 上连接器的 `relay.key` |
| 隧道口令 | 第 5 章 | VPS 的 `frps.toml`、电脑上的 `frpc-screen.toml` |
| 中继的共享密钥（两把） | 第 8 章 | 中继那台的 coturn、VPS 的 `crossdesk.service` |

**这些都别发群、别截图、别贴进任何文档、别提交进仓库。** 仓库里的 `.gitignore` 已经把 `deploy/door.json`、`deploy/site.json` 这类挡在外面了（待整理），提交前还是自己看一眼。
