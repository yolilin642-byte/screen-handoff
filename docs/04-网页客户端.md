# 第 4 章 · 网页客户端：换上改过的那份

> 这一章做完：手机浏览器打开 `https://<你的域名>/#k=<钥匙>`，出来 CrossDesk 的连接页；填设备号和密码，看见你电脑的屏幕。
> 自建前后端的，看最后一节：怎么把这块小屏嵌进你自己的聊天页。

我们没改 CrossDesk 网页版的程序本身（`web_client.js` 一个字没动），只做了三件事：

1. 首页 `index.html` 里塞一份配置：信令地址、STUN，还有我们自己用的几项；
2. 加一个小脚本 `kael_door.js`：拿着钥匙去敲第 3 章那扇门，没钥匙就摆一格「配对码」；
3. 加一个小脚本 `kael_embed.js`：被嵌进别的页面时，自己连、跟外面报状态、听外面的话。

首页不手改，由 `web/build.mjs` 照你的 `site.json` 生成。上游以后更新了，重新生成一遍就行。

---

## 1. 填 site.json

把仓库根目录的 `site.example.json` 抄一份成 `deploy/site.json`，改这几格：

| 格子 | 填什么 |
|---|---|
| `signal` | `self`：信令在你自己的 VPS（第 1、3 章）。`public`：借 CrossDesk 官方的公共信令（见 README「先认一认你家」第 3 种） |
| `domain` | 放这份网页的域名，只写域名，比如 `screen.example.com` |
| `iceServers` | STUN。有自己的中继（第 8 章）就写它，没有就用示例里那个 |
| `chatOrigins` | 要把小屏嵌进去的聊天页的来源，比如 `https://chat.example.com`。没有就留空 |
| `cardOrigins` | 聊天应用直播卡那个框的来源，第 7 章拿到以后再回来填 |
| `deviceId` | 你电脑上 CrossDesk 显示的设备号 |

这份里没有钥匙，钥匙在 `deploy/door.json`，别混在一起。

## 2. 生成

要装 Node.js 18 以上和 git。在仓库根目录，先把上游的网页客户端拉下来，钉在我们照着改的那一版：

```bash
git clone https://github.com/kunkundi/crossdesk-web-client web/crossdesk-web-client
git -C web/crossdesk-web-client checkout e00b64f
```

然后生成：

```bash
node web/build.mjs
```

上游往后的版本我们没试过；想跟新，换掉 `checkout` 那个版本号重新生成，连上验一遍。

生成在 `web/dist1/`。看到 `built … → <你的域名>` 就对了。

## 3. 传上 VPS

`/var/www/screen` 属于 root，直接 scp 进去会被拒，先传到临时目录再挪：

```bash
# 在你的电脑上
scp -r web/dist1 <用户>@<VPS>:/tmp/screen-web

# 在 VPS 上
sudo cp -r /tmp/screen-web/. /var/www/screen/
sudo chown -R root:root /var/www/screen
sudo find /var/www/screen -type d -exec chmod 755 {} +
sudo find /var/www/screen -type f -exec chmod 644 {} +
```

**目录别给 777**（我们家曾经是，谁都能改网页）。

再给 Caddy 加一行，让首页和两个小脚本每回都跟服务器核一下有没有新的（不然手机会拿着旧首页配新脚本，认不出外层）。把第 3 章最后那个 `handle { … }` 改成：

```caddy
	handle {
		@fresh path / /index.html /kael_door.js /kael_embed.js
		header @fresh Cache-Control no-cache
		root * /var/www/screen
		file_server
	}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile && sudo systemctl reload caddy
```

`signal` 选 `public` 的，不用 VPS：把 `web/dist1/` 整个传到 Cloudflare Pages 之类放静态网页的地方就行。

## 4. 验

手机浏览器打开：

```
https://<你的域名>/#k=<钥匙>
```

- 页面会把钥匙记进这台手机，再把它从地址栏里抹掉。
- 填设备号、CrossDesk 密码，点连接，看见电脑屏幕＝成了。
- 出来的是一格「配对码」：钥匙不对，或者没带上。对一下第 3 章那两把钥匙。
- 一直连不上：看第 9 章。

## 5. 给自建前后端：把小屏嵌进你的聊天页

在你的页面里放一个 iframe：

```html
<iframe src="https://<你的域名>/#embed&id=<设备号>&k=<钥匙>"
        allow="autoplay; fullscreen; clipboard-read; clipboard-write" referrerpolicy="origin"></iframe>
```

- `#embed`：被嵌模式。只认 `site.json` 的 `chatOrigins` 里那几个来源的页面（看 referrer，所以 `referrerpolicy` 别设成 `no-referrer`），别的页面嵌了它也不理。
- `&k=<钥匙>`：可选。递一次它就记住，以后不用再带；钥匙最好由你的后端临时递过去，别写死在前端代码里。
- `&mini`：只要画面、低画质，不问密码、不出按钮、不接手指，当一张会动的图用。没存过密码就报 `needpwd`，外面退回静态图。
- 第一次要用户在框里亲手输一次 CrossDesk 密码，之后记在这台设备上，自己连。

它往外报的（`parent.postMessage({kaelLive: …})`，只发给认过的那个来源）：

| kaelLive | 意思 | 附带 |
|---|---|---|
| `connecting` | 在连 | |
| `needpwd` | 要用户输东西 | `why`：`first` 头一回、`wrong` 密码错、`door` 缺钥匙；卡里还有 `idle` 闲太久、`hidden` 切出去太久、`manual` 按了断开 |
| `live` | 出画面了 | `vw`、`vh`：画面的宽高 |
| `failed` | 没连上 | `why: 'timeout'`（二十秒没登上信令），或 `msg`：网页版自己报的那句 |
| `closed` | 断了 | |
| `stopped` | 收到 `stop`，停好了 | `requestId` |
| `qos` | 线路的数（帧率、码率、丢包、直连还是走中继） | 一串数 |
| `paircode` | 回给外面一个「新设备的码」 | `code`、`min`，或 `err` |

外面能说的（`frame.contentWindow.postMessage({kaelControl: …}, 'https://<你的域名>')`）：

| kaelControl | 意思 |
|---|---|
| `cut` | 断开，清掉密码格 |
| `stop` | 断开、收掉它自己所有的计时器，不再自己重连；回一声 `stopped` |
| `paircode` | 拿这扇框的钥匙去家里要一个六位「新设备的码」（`requestId` 原样带回） |

聊天应用里的直播卡用的是 `#embed&card` 模式，多几条（`hold`、`hold-state`，接手和还手），细节在第 7 章。
