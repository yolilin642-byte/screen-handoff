# 第 8 章 · 中继（可选）

> 这一章做完：手机和电脑打不通直连的时候（有的校园网、公司网、手机流量），画面绕到中继上转一手，照样看得见。
> 没有它，多数时候也能用：我们家小屏的五百多条连接记录里，`direct`（直连）506 条，`relay`（走中继）3 条。那一回走中继也顺：30 帧、往返 30 毫秒、不丢包。可以等真撞上「连不上」再回来做。

画面是 WebRTC：手机和电脑先各自问一声「外面看我是哪个地址」（STUN），然后试着直接连对方。两头都在严的网后面，直连打不通，就得找一台两边都连得到的机器替它们转（TURN）。这台机器就是中继。

用的是 [coturn](https://github.com/coturn/coturn)，最常见的开源 STUN/TURN 服务器，CrossDesk 自己的部署说明也用它。

---

## 1. 放在哪

中继只走 UDP（和 TCP 3478），连的是 IP，**不用域名、不用证书**。所以第 1 章那条「国内没备案会被掐」管不到它：

- 手机在国内的话，**中继放国内最好**，离得近、转一手也快。我们家信令在东京，中继在广州。
- 跟信令放同一台 VPS 也行，CrossDesk 官方就是这么摆的。
- 它吃的是流量：真走中继时，画面每秒几 Mbit 都从它身上过。挑带宽够、流量不太贵的机器。

我们家这台：腾讯云广州，4 核 4G，OpenCloudOS 9，coturn 跑在 docker 里，平时几乎没事干。

## 2. 防火墙

这几个口放进来（云厂商控制台的安全组／防火墙，加上机器里自己的那层，两边都要）：

| 口 | 协议 | 干嘛 |
|---|---|---|
| 3478 | UDP | STUN、TURN |
| 3478 | TCP | TURN 走 TCP（UDP 被封的网才用得上） |
| 50000–50100 | UDP | 中继真转画面的口，一路画面占一两个 |

CrossDesk 的说明里写的是 50000–60000。一家人用，我们开 101 个够了；范围改了，下一步 `--min-port`、`--max-port` 跟着改。

## 3. 一把共享的密钥

中继不给不认识的人转。认法是：信令和中继手上有同一把密钥，信令拿它给每个连进来的人现算一张临时通行证（一小时有效），中继拿同一把密钥验。

```bash
openssl rand -hex 32   # 共享密钥
openssl rand -hex 32   # 再来一把，给 coturn 内部用（stateless nonce）
```

跟第 3 章的门钥匙一样：**别发群、别截图、别进仓库。**

## 4. 起 coturn

在中继那台机器上（装好 docker）：

```bash
sudo docker run -d --name coturn --restart unless-stopped --network host \
  coturn/coturn:4.17.2-r0-debian turnserver \
  --listening-port=3478 \
  --external-ip=<中继的公网 IP>/$(hostname -I | awk '{print $1}') \
  --min-port=50000 --max-port=50100 \
  --use-auth-secret --static-auth-secret=<共享密钥> \
  --stateless-nonce-secret=<第二把> \
  --realm=crossdesk \
  --no-cli --no-tls --no-dtls --fingerprint --no-multicast-peers \
  --denied-peer-ip=10.0.0.0-10.255.255.255 \
  --denied-peer-ip=172.16.0.0-172.31.255.255 \
  --denied-peer-ip=192.168.0.0-192.168.255.255 \
  --log-file=stdout --simple-log --log-min-level=warning
```

几处要知道的：

- `--external-ip=公网/内网`：云机器的网卡上多半只有内网地址，公网 IP 是云厂商在外面映射的。写成「公网/内网」，coturn 才知道该把哪个地址告诉别人。
- `--denied-peer-ip` 那三行**别删**：不许中继往私有网段转。不加的话，拿到通行证的人可以借你的中继去摸中继所在机房的内网。
- `--no-tls --no-dtls`：画面本身是 WebRTC 加过密的，中继只是转包，不用再套一层。
- **国内机器拉不动 Docker Hub**：换云厂商自己的镜像源。我们家用的是腾讯的：`mirror.ccs.tencentyun.com/coturn/coturn:4.17.2-r0-debian`。
- 不想用 docker，系统包管理器里装 `coturn`，把上面这串参数写进 `/etc/turnserver.conf`（一行一个，去掉开头的 `--`），效果一样。我们家没这么装过。
- **两台机器的钟要准**：通行证上写着过期时间，钟差太多会被当成过期。云机器一般自带对时，`timedatectl` 看一眼 `System clock synchronized: yes`。

## 5. 告诉信令

回到第 1 章那台 VPS，`/etc/systemd/system/crossdesk.service` 的 `[Service]` 里加：

```ini
Environment=EXTERNAL_IP=<中继的公网 IP>
Environment=COTURN_PORT=3478
Environment=COTURN_AUTH_SECRET=<共享密钥>
Environment=COTURN_CREDENTIAL_TTL_SECONDS=3600
Environment='CROSSDESK_ICE_SERVERS=[{"urls":["stun:<中继的公网 IP>:3478"]},{"urls":["turn:<中继的公网 IP>:3478?transport=udp","turn:<中继的公网 IP>:3478?transport=tcp"]}]'
```

- `EXTERNAL_IP` 在 CrossDesk 的说明里指「这台机器的公网 IP」，因为官方把信令和 coturn 放在一起。**拆开放的话，这里填中继的 IP**，信令发通行证时会告诉两头「去这个地址找中继」。我们家就是这么填的，用得了。
- `CROSSDESK_ICE_SERVERS`：信令每回牵线，都把这张单子连同通行证发给手机和电脑，两头用同一套。整段外面那层单引号别丢，不然 systemd 会把 JSON 里的空格和引号拆坏。
- 第 1 章已经 `chmod 600` 过这份文件，密钥在里面，别让别人读。

```bash
sudo systemctl daemon-reload
sudo systemctl restart crossdesk
```

网页客户端那头（`site.json` 的 `iceServers`）只在信令老到不发这张单子时才用得上。照我们家写一个 STUN 就行：`[{"urls":["stun:<中继的公网 IP>:3478"]}]`。**TURN 和密钥别往 `site.json` 里写**，它会被生成进网页，谁都看得见。

## 6. 验

**从外面要一个通道。** 仓库里 `tools/turn-check.cjs`：

```bash
TURN_HOST=<中继的公网 IP> KT_SECRET=<共享密钥> node tools/turn-check.cjs
```

| 回 | 意思 |
|---|---|
| `udp stun reply type 101` | STUN 通了 |
| `TURN allocate OK, relay <IP>:<口>` | 通行证认了、中继给了一个 50000–50100 里的口 |
| `TURN reply type 113 … err` 卡在这儿 | 通行证不认：密钥对不上，或者钟差太多 |
| 什么都没回 | 3478/UDP 没放进来 |

隔一会儿多跑几回。UDP 丢一个包就少一行回话：我们家这台电脑开着代理跑，四回里有一回 STUN 没回、另一回 TURN 最后一步没回，其余都好。偶尔一回不算坏；回回不回才是。

**再看真连时走的是哪条。** 第 4 章的小屏、第 7 章的直播卡，连上以后状态那行会写 `direct`（直连）或 `relay`（走了中继），后面可能带 `/udp`、`/tcp`。想专门试中继：手机关掉 Wi-Fi 用流量，或者连一个严的公司网，看它会不会变成 `relay`。

## 7. 要知道的

- 中继 IP 换了（比如换机器）：coturn 的 `--external-ip`、信令那五行里的 IP、`site.json` 的 `iceServers`，三处一起改。
- 共享密钥换了：coturn、信令两处一起换，重起两边。网页那头不用动。
- 中继挂了：已经直连上的照样连着，只有需要中继的网连不上。所以它挂了往往很久都没人发现，隔一阵跑一回第 6 步。
