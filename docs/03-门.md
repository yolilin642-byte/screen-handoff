# 第 3 章 · 门：给信令挂上钥匙

> 这一章做完：不带钥匙的人，连 CrossDesk 的密码框都摸不到；你的电脑和你的手机照常连得上。

第 1 章做完时，信令对整个网开着：谁知道你的域名，谁就能打开网页客户端，填设备号、猜密码。CrossDesk 的密码最多六位，那就是全部的锁。

这一章在信令前面再挂两把钥匙，CrossDesk 的密码退成第二道锁：

| 谁来连 | 走哪扇门 | 凭什么进 |
|---|---|---|
| 你的电脑（CrossDesk 主机端） | `/h/<门牌>` | 门牌：一串别人猜不到的路径 |
| 网页客户端（手机浏览器、聊天应用的直播卡、你自己的聊天页） | `/?k=<钥匙>` | 钥匙：一串别人猜不到的字 |
| 别的 | — | 一律 403 |

为什么电脑和网页各用一把：CrossDesk 主机端连信令时带不了 `?k=` 这种参数，只认「域名/路径」，所以给它一个藏起来的路径；网页客户端改过（第 4 章），会带着钥匙来。

---

## 1. 生成两把钥匙

在 VPS 上（或者任何有 openssl 的地方）：

```bash
openssl rand -hex 12   # 门牌，比如 3f9c...（24 个字）
openssl rand -hex 16   # 钥匙，比如 a71e...（32 个字）
```

记在只有你看得见的地方。**别发群、别截图、别贴进任何文档**，包括这个仓库。

> 我们家踩过一回：查配置的时候想把钥匙那几行滤掉，滤的写法写错了，钥匙原样打进了命令输出。往后查配置，带钥匙的行只看名字、不看值。

## 2. Caddy：只放带钥匙的进来

把第 1 章那段 `<你的域名> { … }` 换成下面这样（`<门牌>`、`<钥匙>` 换成你的）：

```caddy
<你的域名> {
	# 电脑上的 CrossDesk 走藏起来的门牌，进去以后当成根路径交给信令
	@hostws {
		path /h/<门牌>
		header_regexp Upgrade (?i)websocket
	}
	handle @hostws {
		rewrite * /
		reverse_proxy https://127.0.0.1:9099 {
			transport http {
				tls_insecure_skip_verify
			}
		}
	}

	# 网页客户端带着 ?k=<钥匙> 来
	@webws {
		query k=<钥匙>
		header_regexp Upgrade (?i)websocket
	}
	handle @webws {
		reverse_proxy https://127.0.0.1:9099 {
			transport http {
				tls_insecure_skip_verify
			}
		}
	}

	# 网页先问一声钥匙对不对：对的回 204，不对的回 403
	@doorok {
		path /door
		query k=<钥匙>
	}
	handle @doorok {
		header Cache-Control no-store
		respond 204
	}
	handle /door {
		header Cache-Control no-store
		respond 403
	}

	# 不带钥匙、不走门牌的信令一律不放
	@signal header_regexp Upgrade (?i)websocket
	handle @signal {
		respond 403
	}

	handle /stats {
		reverse_proxy https://127.0.0.1:9099 {
			transport http {
				tls_insecure_skip_verify
			}
		}
	}

	handle {
		root * /var/www/screen
		file_server
	}
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

**改完的那一刻，你电脑上的 CrossDesk 会被踢下线**（它还在走老门），做完下一步就好。

## 3. 电脑上的 CrossDesk：换成走门牌

要 CrossDesk 桌面端 **v1.7.4 或更新**：老版本不认「域名/路径」这种写法。

在 CrossDesk 的设置里打开自建服务器：

- 服务器地址：`<你的域名>/h/<门牌>`
- 端口：`443`

我们家用的是免安装版，改的是程序目录下 `data\config.ini` 里这两格：

```ini
signal_server_host = <你的域名>/h/<门牌>
signal_server_port = 443
```

改完重开 CrossDesk。窗口上显示已连接服务器、设备号还在，就对了。设备号存在别处，不跟着地址变，换门牌以后还是原来那个。

## 4. 验：从外面敲几下

找一台**不是这台 VPS** 的机器（你的电脑就行），一样样敲：

| 敲法 | 应该 |
|---|---|
| `https://<你的域名>/door` | 403 |
| `https://<你的域名>/door?k=<钥匙>` | 204 |
| 不带钥匙连 `wss://<你的域名>/` | 403 |
| 带钥匙连 `wss://<你的域名>/?k=<钥匙>` | 连得上 |
| `nc -vz -w 5 <VPS 的 IP> 9099` | 连不上（第 1 章的防火墙） |

前两条浏览器打开就能看。后面两条要一个会连 WebSocket 的小工具，仓库里有一份 `tools/door-check.mjs`：在仓库目录里 `node tools/door-check.mjs`，它读 `deploy/site.json` 和 `deploy/door.json`，七下逐个敲完告诉你哪下不对，不打印钥匙。要 Node 22 以上。

## 要知道的代价

- **手机上的 CrossDesk App** 也得把服务器地址改成带 `/h/<门牌>` 的，不然进不去。我们家没在 App 上真试过。我们平时都从网页进，所以没管它。
- 钥匙怎么交到网页手里：第一次直接开 `https://<你的域名>/#k=<钥匙>`（`#` 后面那段不会发给服务器，也就不进任何日志），网页记进这台设备、顺手把它从地址栏里抹掉，以后就不用再带。网页连信令时，再由它自己接到 `wss://…/?k=` 上。更好的办法是配对码：已经进过门的设备点一下，给新设备出一个六位数、十分钟有效的码，新设备拿码换钥匙，钥匙本身不用经你的手。这要屏幕小程序和隧道（第 5 章）。
- 钥匙要是露了：重新生成，改 Caddy、改 CrossDesk 那两处，记过旧钥匙的设备都得重新配一次。
